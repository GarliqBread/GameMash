# GameMash agent guide

Product spec, decisions, progress and open questions: [docs/spec.md](docs/spec.md). Read it before starting work. Setup, URLs and environment variables: [README.md](README.md).

## How we work

- Propose a plan before writing code. Keep changes small and reviewable.
- Don't fill gaps with assumptions. Ask when the spec is missing something.
- Anything under "Open questions" in the spec is not decided. Discuss before implementing.
- Never create git commits. The maintainer commits.
- Before handing work back: run lint, typecheck and tests, and check UI changes in a real browser (Playwright against `pnpm dev`, or Ladle for components).
- When reviewing, be critical and verify findings (read the code, reproduce) before reporting them.

## Layout

- `apps/api`: Fastify, Socket.io, Redis
  - `sessions/`: REST routes (sessions, join, avatars, setup and its `.gamemash` export/import in `setup-transfer.ts`), `service.ts` (business rules), `store.ts` with a Redis store (Lua scripts in `scripts.ts`) and an in-memory store that share one contract test
  - `game/`: the phase engine. `engine.ts` holds the pure transitions; `runner.ts` runs one queue per session, owns the phase timers, picks them up again after a restart and builds per-viewer snapshots (`game:state`). Phases whose input is too large for a socket message (Draw it drawings) take it by upload instead (`upload-routes.ts`); the game's rules validate it and decide who may fetch it back
  - `lobby/`: Socket.io lobby (handshake auth, per-member connection caps, presence, batched `lobby:state` broadcasts, keep-alive, 6-hour deadline, session end)
  - `media/`: question image storage. `ImageStore` with a disk implementation (production default, served at `/api/images`), an optional S3 one (signed with `aws4fetch`, MinIO in tests) and an in-memory one, sharing one contract test. Uploads are capped per session and server-wide; a sweep removes images of expired sessions
  - `limits/`: client keys (IPv6 grouped per /64) and an in-memory rate limiter
- `apps/landing`: Astro static landing page for `gamemash.io`. Sections in `src/components`, all copy and links in `src/content.ts`, `PUBLIC_PLAY_URL` points at the app (default `https://play.gamemash.io`). No client JavaScript beyond the phone menu; the CSP is generated by Astro, so no inline `style` attributes.
- `apps/web`: Vite SPA with React, TanStack Router (file-based) and Query, Zustand, Tailwind v4, Base UI, react-intl
  - `routes/`: `/host` → `/host/$sessionId/setup` (workshop) → `/host/$sessionId` (lobby); `/`, `/join/$code` → `/play/$sessionId`; `/join?code=` (the landing page form) redirects to `/join/$code`. `host.$sessionId.tsx` is a layout that owns host credentials and the socket for its child routes.
  - `features/`: screens and their hooks, grouped by feature (`join`, `lobby`, `play`, `setup`, `session`, `host`)
  - `lib/`: API calls, credentials (`sessionStorage` plus an in-memory copy), the lobby socket and its Zustand store, avatar resizing, error translation
- `packages/shared`: types, constants and helpers shared by API and web. TypeBox schemas live only in `@gamemash/shared/schemas`.
- `packages/games`: one folder per game. `definition.tsx` (title, colour, icon, round label) is React; `config.ts` (limits, defaults, readiness helpers, and the `GameRules` contract from `rules.ts` that a game's server logic implements) and `schema.ts` (TypeBox) are not, so the API can import them via `@gamemash/games/config` and `@gamemash/games/schemas`. A game's server logic (`rules.ts`, implementing `GameRules`) is registered in `src/server.ts` and imported by the API from `@gamemash/games/server`; web code may only import its view types (from `@gamemash/games/config`).
- `packages/messages`: ICU message catalogs
- `packages/ui`: `@gamemash/ui` design system (Tailwind v4 tokens in `theme.css`, Base UI primitives, layouts). Stories run in Ladle.

## Code conventions

- No code comments.
- No `readonly` types in web code.
- Keep web tests to a minimum. Test the API and shared packages with Vitest. The store contract tests run against both the in-memory and the Redis store, and the image store contract tests against both the in-memory and the S3 (MinIO) store; they need `pnpm services` (skipped locally without it, required in CI).
- The API returns error codes (`{ code, params? }` from `@gamemash/shared`), never user-facing text. The client translates them with `useErrorMessage()`.
- Every error code needs a message in every catalog. The messages package tests enforce this.
- Message style: no full stop at the end of a message, `...` instead of `…`, numbers through ICU (`{count, number}` or `#` in plurals), limits passed in as values rather than written into the text.
- Web code must not import `@gamemash/shared/schemas` or `@gamemash/games/schemas` at runtime (type-only imports are fine). They pull TypeBox into the bundle.
- The API rejects unknown fields (ajv `removeAdditional: false`). Validate request bodies with TypeBox schemas; check auth in `onRequest` before large bodies are parsed; rate-limit per client address, not only per session.
- Every Redis key carries an expiry. A new session key must be added to the touch script in `sessions/scripts.ts` and to the contract test that checks all TTLs.
- Phones only ever receive what they may see: never quiz answers, tokens or token hashes.
- Socket-driven live state lives in Zustand, never in the Query cache.
- Styling is our own Tailwind on top of Base UI. No shadcn. Links that look like buttons use `buttonVariants` on a real `<Link>`, not a Base UI `Button` rendered as a link.
- `packages/ui/src/theme.css` holds all design tokens. Colours, font sizes, radii and shadows must come from it. New tokens may be added only with the maintainer's approval; the maintainer keeps the design source in sync. It's excluded from Biome. When adding a token that Tailwind utilities use, register it in `packages/ui/src/lib/cn.ts` so `tailwind-merge` doesn't drop it.
- Approved additions so far: `--color-canvas`, `--shadow-tile-*`, `--shadow-card-word`, the per-theme `--gm-*` tokens for primary hover/shadow/press offset, selected, trust icon and danger, `--tracking-pixel` (letter spacing for Silkscreen labels), `--text-key` (19px workshop key buttons and question tabs), `--text-label` (13px), `--text-title-sm` (22px), `--text-title` (26px), `--text-title-lg` (28px), `--text-wordmark-lg` (40px), `--tracking-display` (-0.02em), `--tracking-display-tight` (-0.03em) the drawing colours `--color-draw-gray`, `--color-draw-white`, `--color-draw-brown`, `--color-draw-sky` and `--color-draw-pink`, the entry TV illustration tokens `--shadow-drop-coral`, `--shadow-drop-violet`, `--shadow-drop-lime`, `--shadow-drop-sky` and `--radius-bar`, and the landing page tokens `--text-headline`, `--text-display-sm`, `--text-display`, `--text-display-lg`, `--text-display-xl` (fluid), `--tracking-display-tightest` (-0.045em), `--shadow-brutal-2xl`, `--shadow-brutal-3xl`, `--shadow-brutal-violet`, `--shadow-brutal-violet-2xl`, `--shadow-brutal-sun-2xl` and `--shadow-brutal-white`.
- UI components take all copy through props, contain no game logic or stores, and never persist player data.
- Stage (big screen) components are laid out on a fixed 1920×1080 canvas scaled by `StageViewport`. No breakpoints there.
- Every primitive has a Ladle story in both themes. Use the pseudo-locale toggle to check that long strings don't overflow.
- Shared dependency versions live in the `catalog:` in `pnpm-workspace.yaml`.
- `apps/web/src/routeTree.gen.ts` is generated by the router plugin and is committed. Don't edit it by hand; a `vite build` or `pnpm dev` regenerates it.

## Commands

- `pnpm services`: start Redis on host port 6380 and MinIO on 9000 (console 9001) and create the `gamemash-dev` bucket (override ports with `REDIS_PORT`, `MINIO_PORT`, `MINIO_CONSOLE_PORT`); `docker compose down` stops them
- `pnpm dev`: build shared packages, then run everything in watch mode
- `pnpm stories`: Ladle component stories for `@gamemash/ui` (port 61000)
- `pnpm lint`, `pnpm format`, `pnpm typecheck`, `pnpm test`, `pnpm build`
